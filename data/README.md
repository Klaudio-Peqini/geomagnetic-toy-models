# Data Directory

This directory contains lightweight datasets, metadata, and data-related
notes used by the `geomagnetic-toy-models` repository.

The purpose of this folder is **not** to store large raw scientific
archives. Instead, it is intended for:

-   small reference datasets,
-   synthetic datasets generated by toy models,
-   processed or downsampled benchmark files,
-   metadata describing external paleomagnetic sources,
-   example inputs for notebooks and diagnostics.

------------------------------------------------------------------------

## Philosophy of the `data/` Folder

This repository focuses on **low-dimensional geomagnetic toy models**
rather than full production-scale geodynamo data pipelines. Therefore,
the `data/` directory is designed to remain:

-   lightweight,
-   transparent,
-   version-controllable,
-   easy to inspect,
-   suitable for teaching, prototyping, and reproducible examples.

Large raw datasets should generally **not** be committed directly to
this repository unless they are small enough to remain practical for
Git-based workflows.

------------------------------------------------------------------------

## What Kind of Data Belongs Here

Typical contents of this folder may include:

### 1. Synthetic model outputs

Datasets generated directly from the toy models in this repository, for
example:

-   polarity time series
-   dipole-moment trajectories
-   reversal-event catalogs
-   noisy realizations of bistable or double-well models
-   ensemble outputs from stochastic simulations

These files are useful for:

-   testing diagnostics
-   validating notebooks
-   creating reproducible figures
-   comparing model families

------------------------------------------------------------------------

### 2. Lightweight observational reference data

Reduced or processed forms of geomagnetic or paleomagnetic information,
such as:

-   reversal times
-   excursion markers
-   simplified paleointensity curves
-   dipole reconstructions
-   benchmark comparison series

Whenever such data are included, they should be accompanied by metadata
describing:

-   source
-   preprocessing steps
-   units
-   time conventions
-   citation requirements

------------------------------------------------------------------------

### 3. Metadata and documentation files

The `data/` directory may also contain files that document datasets:

-   data dictionaries
-   provenance notes
-   unit conventions
-   processing logs
-   dataset descriptions

## Recommended File Formats

Preferred formats:

### Tabular / simple text

-   `.csv`
-   `.tsv`
-   `.txt`

Good for:

-   time series
-   reversal catalogs
-   parameter tables

### Structured metadata

-   `.json`
-   `.yaml`
-   `.yml`

Good for:

-   dataset descriptions
-   configuration
-   provenance

### Scientific array formats

-   `.npy`
-   `.npz`

Useful for storing:

-   synthetic trajectories
-   ensembles
-   numerical arrays

------------------------------------------------------------------------

## Data Provenance

Every dataset should ideally answer:

1.  What is the dataset?
2.  Where does it come from?
3.  What processing was applied?
4.  What are the units?
5.  What is the time convention?
6.  Can it be redistributed?
7.  How should it be cited?

Example metadata:

``` yaml
dataset_name: synthetic_domino_reversal_series
source: generated with models/domino_model/simulate.py
description: polarity and dipole proxy time series
time_units: nondimensional
value_units: arbitrary_units
seed: 42
created_on: 2026
```

## Relation to the Rest of the Repository

The `data/` folder supports:

-   `models/` which generate synthetic outputs
-   `diagnostics/` which analyze time series
-   `notebooks/` which demonstrate workflows
-   `docs/` which describe the scientific context

Thus it acts as a bridge between modeling, analysis, and documentation.

## Good Practices

When adding datasets:

### Keep files small

Prefer lightweight datasets suitable for Git.

### Prefer processed subsets

Large archives should remain external.

### Record preprocessing

Document smoothing, filtering, resampling, etc.

### Use clear filenames

Examples:

-   `reversal_catalog.csv`
-   `synthetic_double_well_timeseries.csv`
-   `dipole_proxy_example.csv`

Avoid names like:

-   `data1.csv`
-   `test_output.txt`

### Avoid ambiguous units

Always specify whether values are dimensional or normalized.

------------------------------------------------------------------------

## External Data Policy

For large geomagnetic datasets:

1.  store authoritative data externally
2.  include only lightweight subsets here
3.  document the original source
4.  include citation information

Future versions of the repository may include scripts like:

``` bash
python scripts/fetch_reference_data.py
```

or

``` bash
python scripts/prepare_paleodata.py
```

## Example Use Cases

### Testing diagnostics

Synthetic time series generated by toy models can be stored here and
analyzed with the `diagnostics` scripts.

### Notebook demonstrations

A processed paleomagnetic dataset can be loaded in notebooks to compare
with toy-model output.

### Reproducible figures

Small datasets used in publications can be stored here so that figures
can be regenerated.
